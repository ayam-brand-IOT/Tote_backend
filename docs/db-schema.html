Ayam Brand · Tote Management

Diagrama de relaciones — base de datos

Esquema real definido en Tote_backend/init-db.js (MySQL). Cinco tablas: totes y products como catálogos principales, lines como identidad de la línea física, y dos tablas de enlace temporal (line_product, tote_line) que registran qué estaba activo en cada momento.

PK Llave primaria
FK Llave foránea
Relación 1 → N (columna de origen referencia a la de destino)
Los números en cada extremo indican la cardinalidad (1 = un registro, N = muchos)
products
id PK INT AUTO_INCREMENT
productVARCHAR(255) NOT NULL
typeVARCHAR(255) NOT NULL
sizeVARCHAR(255)
commentsTEXT
created_atTIMESTAMP
updated_atTIMESTAMP
Fish Type / Fish Size del producto (ver src/constants/options.js en el frontend).
lines
line_id PK VARCHAR(255)
commentsTEXT
created_atTIMESTAMP
updated_atTIMESTAMP
Identidad pura de la línea física. Sembradas por defecto: Hybrid, Taichong, Mexican.
line_product
id PK INT AUTO_INCREMENT
line_id FK → lines.line_id
product_id FK → products.id
destinationVARCHAR(255)
started_atTIMESTAMP
ended_atTIMESTAMP NULL
commentsTEXT
Asignación temporal de un producto a una línea. ended_at NULL = asignación activa.
totes
id PK INT AUTO_INCREMENT
tote_idVARCHAR(255) NOT NULL
tote_kgINT UNSIGNED
water_kgINT UNSIGNED
ice_kgINT UNSIGNED
fish_kgINT UNSIGNED NULL
raw_kgINT UNSIGNED
ice_out_kgINT UNSIGNED NULL
water_out_kgINT UNSIGNED
temp_outDECIMAL(5,2) NULL
statusENUM(7 estados)
created_atTIMESTAMP
updated_atTIMESTAMP
status: empty → inbound-ready → product-linked → outbound-ready → in-transit → received-for-packing → offloaded-to-clean.
tote_line
id PK INT AUTO_INCREMENT
tote_record_id FK → totes.id
line_product_id FK → line_product.id
destinationVARCHAR(255)
linked_atTIMESTAMP
Enlaza un tote con el contexto exacto línea/producto activo al momento del enlace. UNIQUE(tote_record_id, line_product_id).
